## Why a table and not a plain document

Each row is one moment in the recording. The table makes the correspondence physical: row 4
of the Arabic is row 4 of the English, and both carry the same timestamp. Nobody has to
count lines or keep two files in sync, and a translator always sees the Arabic right next
to what they are writing.

This is what makes the final website able to say *"he said this at 0:23"* and jump the
listener exactly there. It is the whole basis of the project's trustworthiness, and it
costs nothing as long as the rows stay as they are.

**So: never add, delete, merge or reorder rows.** If one English cell needs to cover two
Arabic rows, write it in the first and leave the second empty. The empty cell is correct;
a deleted row is not.

The admin creates the Doc with Arabic and machine drafts already filled in. Contributors
only correct.

## Review

The admin reviews in the same Doc using **comments**, not by rewriting cells. That keeps
the contributor's work visible, shows exactly what was wrong, and lets them learn from it.
Version history is automatic, so nothing is ever really lost.
